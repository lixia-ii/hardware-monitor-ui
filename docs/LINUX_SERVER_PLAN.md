# Linux 服务器适配方案

日期：2026-11-12。状态：服务器预览代码已实现；Ubuntu 实机、systemd、24 小时运行和升级回退仍待验收。部署见 [Linux 使用说明](LINUX.md)。

## 目标与范围

在当前仓库增加 Linux 服务器模式，与 Windows 版本共用网页、历史、告警和设备管理逻辑。首个实际验收环境为用户提供的 Ubuntu 26.04.1 LTS、x86_64，无桌面环境。

- Windows 继续使用现有桌面入口、LibreHardwareMonitor、托盘和悬浮窗。
- Linux 以普通服务用户运行，通过 systemd 管理；电脑、手机通过浏览器访问。
- 首版交付 CPU 利用率、内存、网速、可读取的温度和风扇、历史曲线、CSV、告警记录、网页设置、硬件概览与诊断。
- 现有 OpenWrt、TP-Link、远程电脑功能复用；Linux 保存 TP-Link 密码时采用新的凭据后端。
- NVIDIA 为按需启用的能力；无显卡或未安装驱动不影响基础监控。
- 首版不做 Linux 桌面、DEB/RPM、Docker 部署、风扇调速、自动加载内核模块、主动消息推送、BMC/IPMI 和全面 AMD/Intel GPU 适配。
- 首版访问定位为本机或可信内网。公网登录认证、TLS 与反向代理支持单独实施；未完成前不作为公网管理服务发布。

## 当前代码中的改造点

| 现有位置 | 当前行为 | 计划调整 |
|---|---|---|
| `__main__.py`、`bootstrap.py` | 提前导入桌面、Win32 托盘；执行 UAC 和 DPI 设置 | 先解析模式、再延迟加载平台入口，Linux 不导入 Tk、Win32、pythonnet |
| `sensors/lhm.py`、`sensors/reading.py` | 硬件树采集与 Windows 解析路径绑定 | 包装为 Windows 采集后端，增加统一采样协议和 Linux 后端 |
| `core/collector.py` | 固定调用 `reading.read()`，使用 `source.last_tree` 发布数据 | 注入后端，消费同一次采集生成的读数和兼容树快照 |
| `ui/main_window.py` 的初始化、`tick()`、退出流程 | 持有服务实例、历史、告警状态，定时处理结果与管理请求 | 提取独立运行控制器；桌面订阅结果并负责绘制与交互 |
| `ui/web_management.py` | 网页 RPC 直接操作桌面对象、设置窗口和悬浮窗 | 通用动作移入控制器，桌面副作用通过 UI 回调处理 |
| `system/webbridge.py` | 有界请求队列等待 Tk 主线程执行 | 保留排队、取消和串行修改语义，由独立控制循环调度 |
| `sensors/hwinfo.py` | WMI / Windows 硬件清单 | 按平台选择实现；Linux 用系统信息和可读的 `/proc`、`/sys` 文件 |
| `system/credentials.py` | Windows DPAPI | 门面按平台选择后端，Linux 使用独立本地密钥加密 |
| `system/webserver.py`、`management_server.py` | Windows 防火墙命令；管理端固定监听所有 IPv4 地址 | 分离监听配置与平台防火墙，Linux 不执行 `netsh` |
| `ui/display.py`、`ui/settings_dialog.py` | 网页代码依赖其中的名称、输入控件定义，间接导入 Tk | 将通用名称移到不依赖 UI 的模块，桌面编辑行为留在 UI |
| `pyproject.toml`、`.github/workflows/check.yml` | 无条件安装 .NET 桥接依赖，CI 只有 Windows | 使用平台依赖条件，增加 Linux 无桌面检查 |

关键约束：仅新增 Linux 传感器文件不足以运行；网页、告警与历史消费必须脱离 Tk 事件循环。保留现有分层规则，`core`、`sensors`、`system` 不引用 `ui`。

## 目标架构

```text
命令行入口 ── 按平台/运行模式选择 ─┬─ Windows 桌面 → UI 回调与绘制
                                 └─ Linux 后台  → 信号与退出管理
                                                 │
                                      共享运行控制器
                                       │           │
                          采集线程与设备线程池      管理请求队列
                               │                  │
                   Windows / Linux 采集后端       HTTP 管理服务
                               │                  │
                          统一采样快照 → 历史、告警、网页状态
                               └────→ 兼容 /data.json 服务（可选）
```

控制器统一拥有配置、最新数据、历史内存窗口、最近告警、服务启停和设置应用。采集线程继续负责采样及 SQLite 写入；不增加第二个历史写入者。管理请求通过现有有界队列交给控制循环处理，HTTP 工作线程不直接修改配置。

Windows 主线程仍独占 Tk。控制器产生的桌面通知、重绘与设置应用事件，通过 UI 队列交给 Tk；桌面编辑提交与网页保存共用配置修改路径，保留版本冲突检测和“保存成功后才发布”的顺序。控制循环不等待 Tk 回调完成，避免相互等待。

## 采集接口与数据约定

新增后端协议，约定一次 `sample(gpu_id, nic_ids)` 返回包含以下内容的快照，具体类型与命名在实现时确定：

- 归一化读数：沿用现有 CPU、GPU、内存、网速、风扇、温度、设备身份等字段及单位。
- 兼容树：供旧 `/data.json` 客户端使用，与本次读数来自同一次采样；不为两个 HTTP 服务重复读取硬件。
- 采集状态与能力：区分正常、预热、局部不可用、整体失败，并提供指标缺失的可解释原因。
- 关闭方法与生命周期：后端在采集线程创建/使用/关闭，保留 Windows 安装驱动后的重新打开能力。

Windows 后端优先包装现有读取、解析和 NVIDIA 兜底代码；Linux 直接生成归一化读数，兼容树由适配器生成，避免为了复用解析器而把数值先格式化为文本再解析。

| 指标 | Linux 首版来源 | 行为约定 |
|---|---|---|
| CPU 利用率 | psutil CPU 计数/百分比接口 | 非阻塞采样；首个差分样本标记预热，不将无效首值作为真实 0% |
| 内存 | psutil 内存接口 | 明确采用可用内存口径：总量减可用量为占用，百分比与字节数一致 |
| 网卡和网速 | psutil 每网卡计数与接口状态 | 按单调时间差计算 B/s；计数回退、设备重建和统计选择改变后重新建立基准 |
| CPU、硬盘、主板等温度 | psutil 温度接口；必要时补充 hwmon 元数据 | 有依据才分类 CPU；无法判断用途的温度保留通用标签 |
| 风扇 | psutil 风扇接口及 hwmon 标签 | RPM 与百分比独立；未知风扇不自动归为 CPU，缺失与真实 0 RPM 区分 |
| 静态概览 | Python 系统接口、psutil、可读的 `/proc`、`/sys` | 首版不要求完整 DIMM/主板资产清单；受权限限制时返回部分结果 |
| NVIDIA（可选） | 现有 `nvidia-smi` 适配；后续可换 NVML | 保留查询超时、缓存、UUID、多卡选择；查询失败只影响 GPU |

默认网卡统计优先可确认的物理上联网卡；只有虚拟接口或无法确定拓扑时，选择明确的默认路由接口并说明口径，支持手动选择。不能将物理口、网桥、容器口与 VLAN 全部无条件相加。

温度和风扇依赖内核驱动、主板接线与标签，psutil 不能绕过驱动限制。需要传感器校准、标签配置时可引入 lm-sensors；不自动执行硬件探测或模块加载。虚拟机/云主机可能完全没有温度和风扇，基础监控应正常工作。

传感器身份不得只使用会随启动变化的 `hwmon0` 编号。优先结合实际设备路径、芯片名和通道；GPU 使用 UUID，网卡身份结合名称及可用设备信息，并处理重复/缺失信息。身份无法可靠匹配时保留独立设备，避免跨设备串用历史或名称配置。

## Linux 系统集成

### 启动与部署

拟新增 `python -m hwmonitor --headless` 入口；Windows 原有命令保持桌面行为，Linux 默认选择服务器模式。提供 `--help`、`--check`、监听地址/端口参数；`--check` 只输出运行环境、依赖和可用能力，不启动持久服务。

Linux 使用独立虚拟环境安装项目，不要求 .NET、PawnIO、Tk 或显示服务器。Python 下限暂沿用项目的 3.11；具体依赖版本应在目标 Ubuntu 的实际 Python 上验证后固定，不假定服务器当前解释器版本。psutil 的不同主版本存在 API 差异，不使用无上限版本依赖。

拟提供 `deploy/systemd/hwmonitor.service`、幂等安装/卸载脚本与部署说明：

- 应用建议安装到独立目录，例如 `/opt/hwmonitor`；也允许用户指定现有代码目录，不绑定当前服务器的 gomoku 路径。
- 使用专用普通用户 `hwmonitor`，systemd 负责自启与异常重启；首次安装系统服务才需要 sudo。
- 数据目录建议 `/var/lib/hwmonitor`，复用 `HARDWARE_MONITOR_DATA_DIR`；运行锁放在独立运行目录，日志进入 journal，并保留有上限的本地诊断日志。
- 使用 Linux 文件锁实现单实例；端口占用、数据目录不可写等致命启动错误返回非零状态，不覆盖其他实例数据。
- 收到 SIGTERM/SIGINT 后停止接受修改、结束采集、关闭 HTTP 服务和 SQLite；网络请求有超时，退出等待有上限。
- 卸载默认保留数据；升级前备份设置、密钥与历史，失败时允许恢复旧版本和对应数据备份。

### 凭据与配置

Windows 保留 DPAPI。Linux 后端拟使用成熟加密库的 Fernet，密钥独立保存到服务数据目录，目录权限 0700、文件权限 0600，创建时即限制权限；日志、网页和诊断均不输出密码或密钥。密钥丢失时提示重新输入，不自动生成新密钥覆盖已有密文。

这用于保护静态配置内容；密钥和密文位于同一主机，不宣称能抵御服务账户或 root 被控制。Windows 的 DPAPI 密文不直接迁移到 Linux，复制配置后需要重新输入设备密码。

### 监听与网页

- Linux 默认仅监听 `127.0.0.1:7076`，可通过 SSH 转发使用；显式配置监听地址后才开放可信局域网。
- 兼容数据服务默认关闭，启用后使用独立端口 8085；端口冲突在启动前校验。
- Linux 不自动修改 UFW/nftables；部署文档提供限定来源范围的开放示例。
- 绑定地址、端口和服务开关通过启动参数/服务配置管理，避免网页修改后失去管理连接。
- 首版继续使用 IP 或 localhost 访问，保留 Host/同源校验和请求上限；域名代理访问需要另外适配允许来源。
- 新增 `platform`、`mode`、`capabilities` 信息，网页按能力隐藏悬浮窗、置顶、桌面关闭行为等选项；服务端同时拒绝不支持的修改，不能只隐藏按钮。
- 已有桌面配置字段可保留在文件中，但 Linux 不执行其副作用；旧 Windows API 返回值通过兼容测试保护。
- 网页将“电脑端操作”改为适合当前模式的说明，传感器缺失不反复弹出全局错误。
- 保留现有选定 GPU 的告警语义；支持多卡选择不等于所有 GPU 同时告警，后者作为后续扩展。

## 开发顺序与每阶段验收

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| 1. 平台隔离 | 延迟导入、依赖条件、采集协议、Windows 包装后端、通用元数据迁移 | Windows 原有测试及 EXE 自检通过；Linux 能安装、执行帮助/检查，不导入 Tk/Win32/.NET |
| 2. 共享运行控制器 | 提取状态、历史消费、告警、管理分发；桌面用事件接入 | Windows 桌面与网页修改保持同步，冲突、排队取消及历史恢复行为不变 |
| 3. Linux 基础采集 | CPU、内存、网卡、温度/风扇、静态概览、兼容树 | 无传感器也可监控；网速差分正确；网页与 `/data.json` 值一致 |
| 4. 完整服务器模式 | 无桌面主循环、能力展示、配置保存、Linux 凭据、退出清理 | 不安装 Tk 也能运行；设备管理可用；重启后配置、密码与历史恢复 |
| 5. 部署与实机验收 | systemd、安装/卸载、文档、Linux CI、目标服务器验证 | 普通用户运行、开机自启、停止/重启无残留，完成一次升级回退演练 |

阶段 3 完成时可交付内部预览；阶段 5 完成并经用户 Ubuntu 实机验证后，才标记正式支持。当前 Windows 开发机能验证协议与模拟采集，不能代替真实 Linux 传感器及 systemd 验证。

## 验证要求

- Windows：现有单元测试、桌面与网页集成检查、便携包构建和 EXE 自检；重点验证托盘、悬浮窗、网页保存与退出。
- Linux：无 DISPLAY、无 Tk、无 pythonnet 环境运行；使用模拟 `/proc`、`/sys` 数据或注入 psutil 结果覆盖差分预热、断卡、计数回退、缺失值、同型号设备及权限不足。
- 后台 HTTP 集成：真实监听临时端口，验证状态、配置并发冲突、超时取消、历史与 CSV、诊断、密码不泄露、不可用能力拒绝和端口冲突。
- 可靠性：单项传感器或 GPU 失败不终止采集；数据库写入失败保留内存监控并报告；设置保存失败不发布新配置；服务停止有界。
- 增加 Ubuntu CI 与独立后台集成测试，Windows 专属测试按平台明确划分，不能通过跳过全部测试假装 Linux 验证通过。
- 实机：核对 CPU/内存与系统工具口径，网速按相同接口及采样窗口对照；温度对照 lm-sensors（可用时）。记录 CPU 型号、Python、内核、显卡与传感器清单。
- 默认 1 秒刷新、5 秒历史采样下持续运行 24 小时，记录采集耗时、CPU/内存、历史增长及错误；确认无持续增长、无长时间停采。性能数值以实测报告为准，不预先承诺。

## 交付物与待实机确认事项

交付同一仓库内的平台后端、共享控制器、Linux 入口、网页能力适配、systemd 模板、安装/卸载脚本、部署说明和两平台验证记录。开发按上述阶段推进，暂不创建独立 Linux 仓库或拆成微服务。

实机阶段需要确认服务器是物理机还是虚拟机、实际 Python 版本、CPU/显卡型号、传感器可见性和期望的访问范围。这些信息影响硬件覆盖和最终部署配置，不阻塞基础架构开发。

## 接口参考

- [psutil 官方 API](https://psutil.io/api/)：CPU、内存、网络与传感器接口，以及版本变化。
- [Linux hwmon 接口](https://www.kernel.org/doc/html/latest/hwmon/sysfs-interface.html)：设备目录、单位、标签与主板差异。
- [NVIDIA System Management Interface](https://docs.nvidia.com/deploy/nvidia-smi/index.html)：Linux GPU 查询、不可用指标及 NVML 建议。
- [cryptography Fernet](https://cryptography.io/en/latest/fernet/)：本地凭据加密与密钥管理约束。
