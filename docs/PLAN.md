# 硬件监控后续计划

本计划按用户价值、实现复杂度和现有架构的适配程度排序。每一项完成后应更新状态，并在需要时补充设置说明和验证方式。

Linux 服务器支持的独立适配方案见 [Linux 服务器适配方案](LINUX_SERVER_PLAN.md)（已实现服务器预览，Ubuntu 26.04.1 LTS / x86_64 实机验收待执行）。

## 阶段一：告警与可用性

目标：让程序能主动提示可能影响稳定性或散热的问题。

- [x] 温度告警
  - 支持 CPU、GPU 温度阈值。
  - 支持在设置页配置提醒开关、阈值和冷却时间。
  - 通过系统托盘通知展示告警，托盘不可用时在主界面显示提示。

- [x] 风扇异常检测
  - 检测 CPU 或 GPU 高温且对应风扇为 0 RPM 的情况。
  - 检测风扇转速长期低于可配置阈值的情况。
  - 未识别到风扇传感器时不产生误报。

## 阶段二：历史数据与诊断

目标：从当前状态展示扩展到问题回溯和趋势判断。

- [x] 历史曲线
  - 记录 CPU/GPU 温度、利用率、内存/显存占用和网络速率。
  - 支持最近 1 小时和 24 小时的趋势查看。
  - 默认每 5 秒采样一次，滚动保留 24 小时；SQLite 持久化并在重启后恢复。
  - 区分显卡身份与网卡选择，保留峰值，支持悬停读数、最高值及 CSV 导出。
  - 支持在独立窗口中查看曲线。

- [ ] 性能概览扩展
  - 评估并展示 CPU/GPU 功耗、频率、硬盘读写速率和电池状态。
  - 传感器不可用时保留现有的空值展示，不显示错误数据。

- [x] 导出诊断报告
  - 导出当前硬件信息、传感器读数、最近告警和程序版本。
  - 初版支持 JSON 与纯文本。
  - 导出内容不包含用户无关的敏感路径或环境变量。

## 阶段三：展示与自定义

目标：让不同使用场景下的信息密度和外观都合适。

- [x] 传感器自定义
  - 允许选择显示或隐藏的传感器。
  - 允许调整各容器内显示顺序、自定义名称和刷新间隔；单位由指标固定，避免误标。
  - 支持固定默认显卡、手动选择统计网卡。
  - 将配置保存到`data/settings.json`。

- [x] 桌面悬浮窗
  - 提供紧凑模式，显示 CPU/GPU 温度和利用率。
  - 支持置顶和拖动位置。
  - 记住悬浮窗的位置与开关设置。

- [ ] 主题与显示适配
  - 提供浅色和深色主题。
  - 支持字体大小、界面缩放和多显示器窗口位置记忆。

## 阶段 3.5：OpenWrt 路由器

目标：在同一界面查看局域网路由器状态，数据来自路由器上的 `prometheus-node-exporter-lua`（`/metrics`）。

- [x] 基础状态卡片
  - 显示温度、CPU 利用率、内存、负载、运行时间和 WAN 上下行速度；CPU 与网速按两次采样的计数器差值计算，计数器归零时本次不出数。
  - 设置页可启用、填写指标地址、选择 WAN 网卡（默认优先 `pppoe-wan`/`wan`，否则取流量最大的物理网卡）。
  - 卡片可展开收起并记住状态，可在自定义显示中改名、隐藏、调整顺序。
  - 路由器离线或解析异常只影响路由器卡片：独立退避重试（最长 30 秒，改地址立即重试），不计入硬件采集的失败计数；电脑硬件采集失败时路由器卡片照常显示。
  - 诊断报告中的采集耗时包含路由器读取时间。

- [ ] 已知问题：与电脑硬件共用采集线程
  - 路由器响应慢时，单次采集最多被拖慢 1 秒（请求超时）。
  - 首次初始化硬件传感器（约几秒）期间路由器卡片也要等待。
  - 彻底解决需要为路由器单独开采集线程；局域网内影响很小，暂缓。

- [ ] 后续可选
  - 路由器温度、WAN 网速写入历史曲线，接入温度告警。
  - 基于 `node_nat_traffic` 按内网设备统计流量排行（需安装 `prometheus-node-exporter-lua-nat_traffic`）。
  - 在悬浮窗与托盘提示中显示路由器温度。

## 阶段四：定位与维护

目标：帮助定位性能波动，并降低维护成本。

- [ ] 进程关联
  - 当 CPU、GPU 或内存持续高占用时，展示资源占用最高的进程。
  - 明确区分系统总利用率与单进程数据，避免造成归因误解。

- [ ] 更新检查
  - 检查本项目发布版本和内置 LibreHardwareMonitorLib 的版本。
  - 只提示更新与提供下载链接，不在后台自动下载安装。

- [ ] 网页管理端访问鉴权
  - 现状：管理端监听 `0.0.0.0` 且无鉴权，同网段任何设备都能读数据、改设置和设备（含让本机请求任意内网地址）；Host/同源校验只防浏览器跨站。
  - 方案：首次启用生成 128 位随机访问码，存于 `settings.json` 的 `management`（不进入网页设置投影）；电脑端显示 `http://IP:端口/#k=访问码` 链接，提供复制和「重置访问码」。
  - 手机打开链接后用访问码换取 HttpOnly、SameSite=Strict 的长期 Cookie，并抹掉地址栏中的访问码；所有 `/api/*` 校验 Cookie（常量时间比较），静态文件保持公开；重置访问码使已配对设备全部失效。
  - Linux 服务器模式启动时把配对链接写入 journal；本机访问建议不免配对。
  - 待定：是否显示二维码（需引入 `qrcode` 或自实现）。剩余风险：HTTP 明文下 Cookie 可被同网段抓包，需 TLS 另行实施。
  - 完成后同步更新 README、`docs/LINUX.md` 和 `test_lan_listener_and_routes_need_no_login`。

## 建议实施顺序

1. 温度和负载告警。
2. 风扇异常检测。
3. 历史曲线。
4. 桌面悬浮窗。
5. 传感器自定义。
6. 导出诊断报告与性能概览扩展。
7. 主题、进程关联和更新检查。

## 每项完成标准

- 功能可从界面开启、关闭或配置。
- 传感器缺失、硬件库初始化失败和外部命令失败时不会导致界面卡死或退出。
- 新设置可保存并在下次启动后恢复。
- 在 README 中补充使用说明。
