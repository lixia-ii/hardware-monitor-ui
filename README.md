# 硬件监控界面

一个简单的 Windows 桌面界面,实时显示 CPU/显卡的温度、利用率、内存/显存占用,网卡实时上传/下载速度,以及 CPU 风扇、显卡风扇、机箱(主板)风扇转速。

## 说明

本项目是在开源项目 [LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor) 的基础上开发的。程序内置并直接调用它的硬件读取库 `LibreHardwareMonitorLib`,不需要再单独安装或启动 LibreHardwareMonitor,运行时只有本程序一个进程。

- **复用的部分**:CPU、显卡、主板、内存、硬盘、网卡等全部硬件的识别与传感器读取,均由 `LibreHardwareMonitorLib` 完成(内置 0.9.6 版官方发布的程序集,未做修改)。本项目通过 [pythonnet](https://github.com/pythonnet/pythonnet) 在进程内加载它。
- **本项目实现的部分**:界面、告警、历史、悬浮窗、传感器数据接口,以及把传感器整理成与 LibreHardwareMonitor `data.json` 相同的结构(格式参照其源码 `HttpServer.cs` / `SensorNode.cs`)。
- **PawnIO 驱动**:读取 CPU 温度和主板风扇需要 PawnIO 驱动。程序附带官方安装程序 `PawnIO_setup.exe`(作者 namazso,来自 LibreHardwareMonitor 仓库,[GPL-2.0](licenses/PawnIO-GPL-2.0.txt),源码 https://github.com/namazso/PawnIO),检测到未安装时提示安装。
- LibreHardwareMonitor 开源地址:https://github.com/LibreHardwareMonitor/LibreHardwareMonitor ,版权归原作者所有,以 [MPL-2.0](licenses/LibreHardwareMonitor-MPL-2.0.txt) 许可证发布。
- 升级硬件库:从上面的仓库下载新版本,用其中的 `LibreHardwareMonitorLib.dll` 及其依赖程序集覆盖 `vendor/LibreHardwareMonitor/`(便携包中为 EXE 旁的 `LibreHardwareMonitor/`)里的同名文件。

## 使用

1. 双击 `start-windows.bat`(或直接运行 `HardwareMonitorUI.exe`)。读取硬件需要管理员权限,界面会请求一次 UAC 确认:
   - 启动后在后台初始化硬件传感器(约几秒),期间提示条显示"正在初始化硬件传感器…";
   - 首次运行若未安装 PawnIO 驱动,会询问是否安装(见下文);
   - 退出时关闭硬件库、释放驱动,不会残留其他进程。
2. 最小化窗口会隐藏到右下角托盘;单击托盘图标恢复窗口,右键菜单可开关桌面悬浮窗、主窗口置顶或退出,鼠标悬停可直接看 CPU/显卡温度。点关闭按钮时默认询问"退出"还是"最小化到托盘",可勾选记住,之后在底栏 **设置** 里修改。程序只允许运行一个,重复启动会唤出已打开的窗口。

主窗口大小和位置由你决定并自动记住，下次启动恢复（原显示器已断开时回到主屏居中）；读数、分组出现或收起都不会改变窗口大小。底部工具栏（设置、历史、硬件信息）固定在窗口底部；主窗口置顶在 **设置 → 常规** 或托盘右键菜单中切换，下次启动恢复，卡片区内容超出时右侧浮出细滚动条，可用鼠标滚轮滚动，滚动条出现与否都不改变卡片宽度。路由器、机箱风扇、水冷泵及各温度分组点击标题行（左侧箭头）即可收起，收起后标题行右侧仍显示摘要（如最高温度、风扇转速范围）。多显卡时点击显卡卡片右上角的型号标签，从下拉菜单中选择要显示的显卡。尺寸随系统 DPI 缩放。
3. **设置 → 常规 → 开机自动启动**:登录后自动在托盘运行并开始监控。通过任务计划程序(任务名 `HardwareMonitorUI`,以最高权限运行)实现,开启或关闭时确认一次 UAC,之后开机不再弹出。移动程序目录后,下次启动会自动修正任务里的路径。
4. 源码运行需要 Python 3.11 以上（推荐 3.13），首次运行前在仓库根目录执行 `pip install -e .` 安装依赖 pythonnet（用于加载 .NET 硬件库，系统需有 Windows 10/11 自带的 .NET Framework 4.7.2 以上）；之后运行 `start-windows.bat`，或 `python -m hwmonitor`。便携 EXE 已内置，无需安装 Python。
5. **设置 → 常规 → 传感器数据接口**（默认关闭）：开启后在 `http://127.0.0.1:8085/data.json` 提供与 LibreHardwareMonitor 网页服务格式相同的数据，原来接 LibreHardwareMonitor 的工具可直接使用；端口可改。再打开 **允许局域网访问** 后，同一局域网的设备可通过 `http://本机IP:端口/data.json` 访问，设置页会列出可用地址；程序会添加一条仅允许本地子网访问的防火墙规则，关闭时自动删除。接口只读。

## 网页管理端

进入 **设置 → 常规 → 网页管理端**，打开 **启用网页管理端**。默认管理端口为 **7076**，可以修改；启用后默认允许局域网访问，不需要额外打开局域网开关。手机与电脑连接同一局域网，在 Safari 打开 `http://电脑局域网IP:7076/` 即可直接进入，电脑端设置页会列出可用地址。

管理端与原有内网 `/data.json` 服务（默认 **8085**）分别监听、分别启停，使用不同防火墙规则；两个服务的端口必须不同。管理端监听 `0.0.0.0`，自动添加仅允许本地子网访问的防火墙规则，关闭后删除自己的规则。当前管理端使用 HTTP，无证书配置和登录鉴权。为防止 DNS 重绑定，管理端只接受用 IP 地址或 `localhost` 访问，使用主机名（如 `mypc.lan:7076`）会被拒绝。

手机网页包含实时总览、设备管理（OpenWrt / TP-Link / 远程电脑）、历史曲线与 CSV 导出、监控/告警/悬浮窗/显示设置、硬件概览、最近告警及诊断导出。设置保存后同步电脑端，另一端有修改时提示重新载入。设备密码仅写入并由电脑 DPAPI 加密，不回传到网页。

在 iPhone Safari 打开管理地址后可通过 **分享 → 添加到主屏幕** 使用。电脑和软件必须保持运行；网页后台不持续采集，当前不提供手机锁屏告警推送。开机启动、驱动安装、管理端口及管理端开关在电脑端操作。

## 告警、历史与悬浮窗

- **温度告警**：在 **设置 → 告警** 中设置 CPU/显卡阈值、持续超温时间、恢复温差及提醒间隔。默认持续超温 10 秒才提醒，降到阈值以下 5°C 才解除；短暂回落和传感器缺失不会清除提醒冷却时间。托盘不可用时在主界面提示。
- **风扇异常检测**：在 **设置 → 告警** 中单独开启（默认关闭），设置最低 RPM 和持续时间。只有对应设备持续高温且风扇低于设定转速时才提醒；无 RPM 传感器、仅有百分比、显卡低温停转均不触发。
- **历史曲线**：点击底栏 **历史** 查看温度、利用率和网速。默认每 5 秒取样，刷新间隔更长时按实际采集节奏记录，保留最近 24 小时，支持 1 小时/24 小时范围、显卡选择、最高值、鼠标悬停读数及 CSV 导出。“显示间隔”默认自动：1 小时视图按 30 秒、24 小时视图按 5 分钟分段，每段保留首尾、最低与最高采样点，按真实时间顺序连成普通折线，减少点数并保留尖峰，不绘制菱形或气泡标记；也可手动选择原始、30 秒、1 分钟、5 分钟或 15 分钟。悬停曲线可查看原始读数和时间，最高值与 CSV 保留原始数据。缺失或长时间断连处留空，精简绘制不会跨越断点；切换显卡、网卡不会混用其他设备的曲线。
- 历史图按指标上下分图，CPU、显卡、内存、显存各占独立绘图区，避免曲线重叠；时间轴和悬停参考线对齐，各图单独显示最高值，利用率统一采用 0–100% 刻度。单显卡直接在图例中显示型号，多显卡选择仅影响显卡与显存曲线；网络视图分别显示上传、下载。能够唯一对应的硬件库与 NVIDIA 历史记录归为同一个显卡选项，曲线、悬停读数和 CSV 导出会包含两种来源的数据；同型号多卡无法唯一对应时保持独立。
- **重启恢复**：默认将历史写入`data/history.sqlite3`，启动时自动恢复。可在 **设置 → 数据与关于** 关闭“保存历史到本地”；关闭后仍保留本次运行的内存历史，已有本地数据保留并在超过 24 小时后淘汰。
- **悬浮窗**:在 **设置 → 常规** 或托盘右键菜单中开启。圆角小卡片显示 CPU/显卡温度、利用率与风扇转速，以及内存占用和网速，利用率附带细进度条。按住任意位置拖动，松手时靠近屏幕边缘会自动吸附；贴住左、右或上边后，鼠标移开会缩进屏幕外，只露出一条按 CPU 温度着色的细边，鼠标碰到即滑出（边外侧有其他显示器或任务栏时不隐藏）。双击打开主窗口；右键菜单可切换置顶、贴边自动隐藏、显示项目（内存/网速）和不透明度，或关闭悬浮窗。位置与这些选项在下次启动时恢复。

## 加入设备

在 **设置 → 设备** 中点击 **加入设备**，在下方设备的展开内容中选择设备类型，目前支持 **OpenWrt**、**TP-Link（原厂固件）** 和 **远程电脑**，可混合加入多台设备。已有路由器配置会自动保留。每台设备有独立的名称、地址、监控开关和主界面卡片；设置页与主界面均可分别展开/收起，并记住状态。在“自定义显示”的“可选分组”中可逐台改名、隐藏或调整顺序。

### TP-Link 原厂路由器

适配 TL-XDR3040 易展版使用的原厂登录与 `/ds` 状态接口，无需刷机或安装服务。进入 **设置 → 设备 → 加入设备**，选择 **TP-Link（原厂固件）**，填写管理地址（例如 `http://192.168.0.1`），在 **管理员密码** 中输入管理密码，点击 **保存并连接**，会自动开启监控。密码框留空时点击按钮会使用已保存的密码重连，输入新密码则替换旧密码；修改管理地址后已保存的密码会被清除，需要重新输入，避免把密码发给新地址。

密码由 Windows DPAPI 加密后保存在配置中，仅当前 Windows 用户可读取；复制配置到其他电脑或用户后需要重新输入。密码和登录会话不放入采集数据、传感器数据接口或诊断报告。登录失败后停止自动重试，重新输入密码或点击 **保存并连接** 再试。

设备卡片显示连接状态、WAN 联网状态、WAN 在线时长、IP、在线设备数和 WAN 上下行速度（字节/秒）。WAN 在线时长来自本次 WAN 连接的 `up_time`，与路由器开机时长不同；连接中、断开或异常会在卡片上明确显示，收起卡片也能看到断线提示。指标取决于固件提供的数据，缺失时显示 `--`；当前适配不提供 CPU、内存和温度。WAN 网速跟随 **设置 → 监控 → 刷新间隔**（默认 1 秒，最快 0.5 秒），断线清空旧读数并退避重试，最长间隔 30 秒。已在 TL-XDR3040 易展版上验证真实登录、WAN 读数与在线设备表，其他型号和固件版本未保证兼容。

- **终端流量排行**：展开路由器卡片，在下方查看终端的实时上传和下载速度，按两者之和降序排列；选择终端可查看名称和 IP。列表最多显示 6 行，可滚动查看其余终端。终端表和设备数量每 2 秒更新一次（全局刷新更慢时跟随全局节奏），与 WAN 网速分开采集。读取终端失败时显示不可用，不继续显示旧排行。
- **设备在线状态变更提醒**：默认开启，可在该路由器的设置中单独关闭。按 MAC 地址识别终端，状态变化持续至少 3 秒并经后续有效采样确认后，用 Windows 托盘提醒；同批变化合并为一条消息。首次启动、关闭后重新开启提醒、路由器断连或终端表读取失败后的恢复，均重新建立基准，不集中提醒所有终端上下线。托盘不可用时在主界面提示条显示。提醒需要程序持续运行，检测时间还取决于路由器更新终端表的速度。

该固件的 WAN `up_speed` / `down_speed` 单位是 KB/s（1024 字节），程序先乘以 1024 再使用统一的网速格式显示；在线设备表的同名字段则是 B/s，两者单位不同。WAN 统计与本机网卡的范围、采样时刻不同，短时数值可能不同。

### 远程电脑

1. 在对方电脑启动“硬件监控”，进入 **设置 → 常规 → 传感器数据接口**，开启 **启用传感器数据接口** 和 **允许局域网访问**。
2. 在本机 **设置 → 设备** 点击 **加入设备**，展开新增设备后将 **设备类型** 设为 **远程电脑**。
3. 填写对方电脑显示的地址，例如 `http://192.168.1.8:8085/data.json`（只填 `http://IP:端口` 会自动补全 `/data.json`），打开 **显示设备状态**。

远程卡片显示对方的 CPU、显卡、内存、显存、风扇、其他温度及网速。未提供的指标显示 `--`，不会使用本机硬件补值。断线时清空旧读数并逐步延长重试间隔，最多 30 秒；恢复后自动继续显示。远程数据只用于实时显示，本机的历史和告警继续使用本机读数。

### OpenWrt 路由器

可选显示 OpenWrt 路由器的温度、CPU 利用率、内存、负载、运行时间和 WAN 上下行速度。数据来自路由器上的 [`prometheus-node-exporter-lua`](https://github.com/openwrt/packages/tree/master/utils/prometheus-node-exporter-lua)：它是 Prometheus node exporter 的 Lua 精简版，在 9100 端口以纯文本（每行"指标名 + 数值"）提供系统状态，只提供数据，不画图、不存历史。

**1. 在路由器上安装并启动**（温度需要 `-thermal` 附加包）：

```sh
opkg update
opkg install prometheus-node-exporter-lua prometheus-node-exporter-lua-thermal
/etc/init.d/prometheus-node-exporter-lua enable
/etc/init.d/prometheus-node-exporter-lua start
```

**2. 允许局域网访问。** 该服务默认可能只监听本机，Windows 访问不到。在路由器上检查：

```sh
netstat -lnt | grep 9100
```

- 显示 `0.0.0.0:9100` 或 `:::9100`：已可从局域网访问；仍打不开时检查防火墙。
- 显示 `127.0.0.1:9100`：只监听本机，改为监听 lan（想监听所有接口，把 `lan` 换成 `*`）：

```sh
uci set prometheus-node-exporter-lua.main.listen_interface='lan'
uci commit prometheus-node-exporter-lua
/etc/init.d/prometheus-node-exporter-lua restart
```

**3. 验证并启用。** 在 Windows 浏览器打开 `http://<路由器 IP>:9100/metrics`，能看到 `node_load1 0.15` 这类文本即可。然后在 **设置 → 设备** 中点击“加入设备”，在新增设备内选择“OpenWrt”，可配置多台设备，每台可独立命名、删除、启停并选择 WAN 网卡；旧版单路由器配置会自动保留。为每台设备打开“显示设备状态”，并填写指标地址（默认 `http://192.168.1.1:9100/metrics`）。WAN 网卡默认自动选择（优先 `pppoe-wan`/`wan`，否则取流量最大的物理网卡），也可以手动指定。路由器离线只影响路由器卡片，重试间隔逐步延长至 30 秒。

## 自定义、诊断与常驻开销

- **设置 → 监控**：调整刷新间隔（0.5–30 秒）、固定默认显卡、选择网速统计方式。默认自动汇总物理网卡；切换为“手动选择网卡”后可勾选 VPN/虚拟网卡，也可全部取消。显卡卡片上的切换选择也会保存。
- **自定义显示、名称和顺序**：在 **设置 → 监控 → 自定义…** 中先选择 CPU、显卡、可选分组或具体传感器分组，再修改名称、显示状态（双击或按空格切换，隐藏项变暗）和顺序，最后点击“保存”；“恢复默认”可还原当前分组。切换选中项会保留待保存的编辑，“取消”会放弃本次编辑。动态传感器按设备身份保存偏好，其他设备断连或顺序变化不会影响配置。隐藏不影响采集、告警和历史记录。
- **设置窗口**：参考 Windows 11 设置，左侧导航切换“常规 / 监控 / 告警 / 设备 / 数据与关于”（Ctrl+Tab 切换页面）。每项设置一行，左侧是名称和说明，右侧是开关、下拉框或带单位的数值框；修改即时生效并保存，依赖总开关的选项在总开关关闭时置灰，输入超出范围会自动修正，无效的设备地址会提示并恢复。自定义显示单独确认保存。
- **多显卡断连恢复**：固定显卡缺失时保留空值，避免自动套用另一块显卡的数据。NVIDIA UUID 选择在硬件库初始化完成后继续有效；同型号多卡无法确认身份时，仅使用 UUID 对应的读数。
- **设置 → 数据与关于 → 导出诊断报告**：导出 JSON 或纯文本，包含程序版本、硬件概览、当前读数、最近 100 条本次运行的告警及最近采集耗时。报告不导出环境变量、异常中的私有路径或原始日志。
- 本地滚动日志为 `data/monitor.log`，最多 3 份，每份 512 KiB。配置用临时文件和原子替换保存；格式错误时使用默认值，写入失败会在界面提示。历史数据库不可用时退回内存历史并提示。
- 使用一个常驻采集线程；主窗口隐藏时停止更新主界面控件，但继续采集、告警和更新悬浮窗。连接失败后重试间隔逐步延长至 30 秒，进程状态查询缓存 10 秒，NVIDIA 兜底缓存 5 秒。新选择或设置可唤醒采集线程。
- 历史写入通过时间索引清理过期与超量记录，避免每次写入扫描全表；曲线缩放重绘合并处理，复用采样快照，鼠标悬停通过二分查找定位读数。
- 数据与配置默认集中保存在程序目录下的 `data/`，请放在有写入权限的位置。开发/测试可用 `HARDWARE_MONITOR_DATA_DIR` 指定隔离目录。

## 首次运行的 PawnIO 提示

首次启动若未安装 PawnIO(或版本低于 2.0),会弹出"安装 PawnIO 驱动"提示,点 **安装** 后运行随附的官方安装程序,其中有一个 `PawnIO Setup` 英文免责声明。

- **这是什么**:PawnIO 是 LibreHardwareMonitor 使用的开源驱动,用来读取 CPU 温度和主板风扇转速,不装这两项就读不到。英文免责声明是开源软件的通用条款("按现状提供,风险自负")。
- **怎么做**:在安装程序里点 **确定** 即可,只需装一次。装好后程序自动重新初始化硬件,无需重启。
- **暂不安装**:其他读数照常显示,提示条会提醒并提供 **安装** 按钮,随时可以再装。开机自启时不弹窗,只在提示条提醒。
- **装完仍读不到**:退出程序后重新运行;若还不行,检查 Windows 安全中心的"内存完整性"是否拦截了驱动。

## 注意

- 读取 CPU 温度和风扇转速需要管理员权限,这是硬件库的要求。
- 硬件传感器初始化期间或初始化失败时,显卡温度、利用率、显存占用和风扇百分比会由 `nvidia-smi` 兜底(仅 NVIDIA);初始化失败会在提示条说明原因,并每分钟重试。
- 网速是所有物理网卡的上传/下载之和,Hyper-V、WSL、虚拟机、VPN 等虚拟网卡不计入,避免重复统计。
- 能显示哪些风扇,取决于主板是否被 LibreHardwareMonitor 识别。部分品牌机(OEM 主板)没有风扇传感器,CPU 风扇和机箱风扇会显示为空。
- 硬盘/内存/网卡温度会自动排除厂商的告警、临界阈值,只显示当前温度。
- 多块显卡时优先显示独显的温度和风扇,核显不参与。
- CPU 温度优先取 `CPU Package`(Intel)/ `Core (Tdie)`(AMD);老款 Ryzen 的 Tctl 有 10~20℃ 偏移,有 Tdie 时不用 Tctl。
- 主板风扇名称含 "CPU" 才算 CPU 风扇;名称含 "Pump" 的归为水冷泵,单独显示(检测到时才出现);其余转速不为 0 的归为机箱风扇。
- 硬件类别按硬件库提供的 `HardwareId` 识别(如 `/intelcpu/0`、`/gpu-nvidia/0`、`/nvme/1`)。
- 调试传感器读取(管理员终端,已执行 `pip install -e .`):`python -m hwmonitor.sensors.reading`。

## Linux 服务器（预览）

已加入无桌面服务器模式，支持 CPU、内存、网速、可读温度/风扇、历史、告警与网页设备管理。NVIDIA 按需使用 `--nvidia`。

在项目根目录执行 `sh start-linux.sh` 即可后台启动，管理端默认监听 `0.0.0.0:7076`，浏览器打开 `http://服务器IP:7076/`。兼容 `/data.json` 的传感器数据接口与桌面版相同，默认关闭，在网页管理端 **设置 → 常规** 中开关、修改端口（默认 8085）和是否允许局域网访问。首次自动创建虚拟环境并联网安装依赖，之后复用环境（需要 Python 3.11+、venv、pip、Bash 和 util-linux）。关闭终端后继续运行，数据保存在项目的 `data/`。管理命令：

```sh
sh start-linux.sh start       # 启动，省略 start 也可以
sh start-linux.sh stop        # 关闭
sh start-linux.sh status      # 状态及 PID
sh start-linux.sh restart     # 重启，沿用上次参数
sh start-linux.sh logs        # 实时日志，Ctrl+C 仅停止查看
```

可指定参数，例如 `sh start-linux.sh start --host 127.0.0.1 --port 8080`；旧的 `start.sh` 会转交给 `start-linux.sh`。旧启动参数中的 `--data-port` 会在下次启动时写入设置并开启数据接口，之后不再沿用，改由网页管理端控制；`sh start-linux.sh --check` 仍为前台环境检查。管理端没有登录认证，请用于可信内网。直接运行 `python -m hwmonitor --headless` 或 systemd 模式仍默认仅本机访问。

安装、systemd、访问与备份见 [Linux 部署说明](docs/LINUX.md)。Ubuntu 实机、24 小时运行与升级回退仍待验收。
